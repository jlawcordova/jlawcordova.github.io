# jlawcordova.com

Personal site and blog of J. Law. Cordova, built with [Astro](https://astro.build) and TypeScript, with plain CSS. It's deployed to GitHub Pages by GitHub Actions.

## Develop

Requires Node.js 22.12 or newer.

```sh
npm install
npm run dev      # dev server at http://localhost:4321
npm run build    # type-check (astro check) and build to dist/
npm run preview  # serve the built site
npm run fetch-accomplishments  # refresh src/data/accomplishments.json from AT Protocol
npm run art      # publish the pixel-art document to the optimized SVGs with Pixel Lab's CLI (see Pixel art below)
npm test         # tests for the fetch, pixel-art and e2e-runner scripts (Node built-ins, no network)
npm run e2e      # browser checks against the built dist/ (run npm run build first)
npm run e2e -- scripts/e2e/accomplishments.e2e.mjs  # one suite only
```

## Writing a post

Create `src/content/posts/YYYY-MM-DD-my-post.md`:

```md
---
title: My Post
tags: space separated tags
categories: architecture
featured-image: /public/YYYY-MM-DD/featured.png
featured-image-alt: short description of the image
description: One-line summary shown on the blog page and in link previews.
---

Post body in Markdown. Fenced code blocks (```ts) are syntax highlighted.
```

The post is published at `/<categories>/<YYYY>/<MM>/<DD>/<slug>/`, the same scheme as the old Jekyll site, so existing links keep working.

## Pixel art

The home page's art is compiled from text sources in the site's Pixel Lab document, `src/assets/pixel-art/jlawcordova.pixellab/`, by [Pixel Lab](https://github.com/jlawcordova/jlawcordova-lab): the Mac app the owner edits in, and the `pixellab` CLI, engine and compiler, installed here as a dev dependency from git. The `pixel-art` skill (`.claude/skills/pixel-art/SKILL.md`) is the full guide, `docs/intents/2026-10-pixel-art-engine/spec.md` is the design, and `docs/intents/2026-10-art-to-pixel-lab/` is the move to the document.

- **Palette** (`palette.mjs`): named colors in two tiers. *World* (32: seven 4-shade material ramps, from highlight to shadow, plus `ink`, `cream` and two skin tones, picked from the island's own shades) is for all art, and *outfit* (at most 16, all used: six clothing ramps) is for clothing on objects that extend `character`.
- **Objects** (`objects/<name>.mjs`): a `sprite` is a pixel map, one string per row, with `keys` mapping each character to a palette name (`.` is transparent). It can have several layers, a layer `class` (such as `cbob`), and frame loops (`wf`, `ff`, `hf`) that compile to the groups `pixel-art.css` animates. An object can `extends` another and replace whole rows or recolor its keys: every Range outfit extends `character`, and the hero island's green truck extends `truck`.
- A `block` is a box on the isometric grid, drawn from its `size` (`[tiles wide, tiles deep, levels high]`) and three face shades: top light, left mid, right shadow. An optional one-tile `surface`, which can loop, is painted over its top. The library (`block`, `tile`, `water`, `tree`) is in `objects/`, and `scenes/library-demo.mjs` places all of it on a 3×3 island.
- **Scenes** (`scenes/<name>.mjs`): objects placed on the 32×16 isometric grid (`at: { tile: [col, row, level] }`) or at pixel offsets (`at: { px: [x, y] }`), in paint order, inside optional groups with `class` or `data-*` attributes. A scene with an `output` is written to `src/assets/pixel-art/<output>`.
- **Rules:** new art uses world colors only, at most 12 colors and 64×64 pixels, and a character's figure is at most 16×24. Every error names the file, layer, frame, row and column.

```sh
npm run art                                               # publish: validate, compile and write every output SVG
npm run pixellab -- check <name>                          # validate one object or scene and what it uses
npm run pixellab -- art preview <name> --scale 3 --out .art-preview/<name>@3x.png   # a review PNG (git-ignored folder)
npm run pixellab -- art preview palette --out .art-preview/palette.png              # the world palette's swatch sheet
npm run pixellab -- art sizes <scene>                     # bytes per object and color, against HEAD
npm run pixellab -- object new <name> [--kind sprite|block] [--width W --height H] [--extends character]
npm run pixellab -- scene new <name>                      # a valid, canonical starter source
npm run pixellab -- help                                  # every command: scene place, object paint, …
```

**Pixel Lab**, the Mac app, opens the document and draws it with the same engine: it places objects, paints them, plays a scene's motion, and **Publish** (⌘B) is `npm run art`. Agents work through its MCP server (`mcp__pixellab__*`), whose saves are proposals the owner approves in the app, or through the CLI above. The loop is edit → `npm run art` → commit the sources and the SVGs together.

**Pixel Lab for Mac**, the owner's native editor (kept in a separate repository), edits the same sources with this checkout's own engine, and saves straight to them. Agents reach it through its `pixellab` CLI and MCP server: they look at renders, arrange scenes and paint objects with the same commands, and their MCP saves become proposals the owner approves in the app. The `pixel-art` skill (`.claude/skills/pixel-art/SKILL.md`) says when to use which.

Sources are kept in one canonical text format, and `npm test` fails if a source isn't canonical or a committed SVG is stale against its sources.

## Deploy

Pushing to `main` runs `.github/workflows/deploy.yml`, which runs `npm test`, fetches the accomplishments, builds the site, and deploys it to GitHub Pages. Pull requests are tested and built but not deployed. The workflow also deploys `main` when the accomplishments MCP server sends a `repository_dispatch` of type `atproto-updated` (after an add or delete), and daily at 03:17 UTC to catch a missed dispatch. The repository's Pages source must be set to **GitHub Actions** (Settings → Pages → Build and deployment → Source).

# jlawcordova.com

Personal site and blog of J. Law. Cordova, built with [Astro](https://astro.build) and TypeScript, with plain CSS. It's deployed to GitHub Pages by GitHub Actions.

## Develop

Requires Node.js 22.12 or newer.

```sh
npm install
npm run dev      # build the art, then the dev server at http://localhost:4321
npm run build    # build the art, type-check (astro check) and build to dist/
npm run preview  # serve the built site
npm run fetch-accomplishments  # refresh src/data/accomplishments.json from AT Protocol
npm run art      # publish the pixel-art document to its SVGs and the blog's thumbnails with Pixel Lab's program (see Pixel art below)
npm run diagrams    # render the blog's diagrams (scripts/diagrams/) to the PNGs the posts embed, with the environment's Playwright
npm test         # build the art, then the scripts' tests (Node built-ins; no network once the program is downloaded)
npm run explainer-export  # the explainer library as transparent PNGs and explainer.pixellib, into .explainer-export/ (see Explainer library below)
npm run e2e      # browser checks against the built dist/ (run npm run build first)
npm run e2e -- scripts/e2e/accomplishments.e2e.mjs  # one suite only
```

## Writing a post

Create `src/content/posts/YYYY-MM-DD-my-post.md`:

```md
---
title: My Post
tags: space separated tags
categories: architecture
featured-image: /public/thumbnails/my-post.png
featured-image-alt: short description of the image
description: One-line summary shown on the blog page and in link previews.
---

Post body in Markdown. Fenced code blocks (```ts) are syntax highlighted.
```

The post is published at `/<categories>/<YYYY>/<MM>/<DD>/<slug>/`, the same scheme as the old Jekyll site, so existing links keep working.

The featured image is a pixel-art thumbnail. Draw its scene as `src/assets/pixel-art/jlawcordova.pixellab/scenes/thumb-my-post.json` (copy another `thumb-*` scene: a small floating island with the post's idea on it, in a 240×126 viewBox, preview-only, with `"image": { "file": "my-post.png", "scale": 5 }`), and run `npm run art`. Draw a diagram as an entry in `scripts/diagrams/diagrams.mjs` and run `npm run diagrams`.

## Pixel art

The home page's art is compiled from text sources in the site's Pixel Lab document, `src/assets/pixel-art/jlawcordova.pixellab/`, by [Pixel Lab](https://github.com/jlawcordova/jlawcordova-lab): the Mac app the owner edits in, and the `pixellab` program (CLI, engine and compiler in one executable), pinned in `scripts/pixellab.mjs` and downloaded from its GitHub release. The `pixel-art` skill (`.claude/skills/pixel-art/SKILL.md`) is the full guide, `docs/intents/2026-10-pixel-art-engine/spec.md` is the design, `docs/intents/2026-10-art-to-pixel-lab/` is the move to the document, and `docs/intents/2026-10-pixel-lab-v0-6/` the move to format 2 and self-contained SVGs.

- **Palette** (`palette.json`): named colors in two tiers. *World* (32: seven 4-shade material ramps, from highlight to shadow, plus `ink`, `cream` and two skin tones, picked from the island's own shades) is for all art, and *outfit* (at most 16, all used: six clothing ramps) is for clothing on objects that extend `character`.
- **Objects** (`objects/<name>.json`): a `sprite` is a pixel map, one string per row, with `keys` mapping each character to a palette name (`.` is transparent). It can have several layers, a layer `class` (such as `character`), frame loops (`wf`, `ff`, `hf`), ambient loops, actions, and states (Pixel Lab v0.8.0): named runs of its frames plus a move of the whole sprite, that loop, or play once and hold or hand over. The character bobs in its `idle` state and hops in its one-shot `hop` state, and the hero island's crane hook and jib, mine cart, crossing gates and signals and open truck change their look through states. The compiled SVG plays all of it by itself. An object can `extends` another and replace whole rows or recolor its keys: every Range outfit extends `character`, and the hero island's green truck extends `truck`.
- A `block` is a box on the isometric grid, drawn from its `size` (`[tiles wide, tiles deep, levels high]`) and three face shades: top light, left mid, right shadow. An optional one-tile `surface`, which can loop, is painted over its top. The library (`block`, `tile`, `water`, `tree`) is in `objects/`, and `scenes/library-demo.json` places all of it on a 3×3 island.
- **Scenes** (`scenes/<name>.json`): objects placed on the 32×16 isometric grid (`"at": { "tile": [col, row, level] }`) or at pixel offsets (`"at": { "px": [x, y] }`, with an optional `level`), drawn back to front by where each stands (Pixel Lab's depth order, with `"depth": "front"` or `"back"` as the one override), inside optional groups with `class` or `data-*` attributes. An item can carry an ambient loop (the clouds' drift) or actions, and start in a `state`; a scene's `motion` keys can switch an item's state. A scene with an `output` is written to `src/assets/pixel-art/<output>`, and one with an `image` to `static/public/thumbnails/<file>`. The page reaches into an SVG only through Pixel Lab's site contract: `data-pixellab`, the document's classes and `data-*` attributes, `data-play` with `animationend` (the Range's A plays the one-shot `hop` state that way), and `data-state`, which the site doesn't use yet.
- **Rules:** new art uses world colors only, at most 12 colors and 64×64 pixels, and a character's figure is at most 16×24. Every error names the file, layer, frame, row and column.

```sh
npm run art                                               # publish: validate, compile and write every SVG and thumbnail
npm run pixellab -- check <name>                          # validate one object or scene and what it uses
npm run pixellab -- art preview <name> --scale 3 --out .art-preview/<name>@3x.png   # a review PNG (git-ignored folder)
npm run pixellab -- art preview palette --out .art-preview/palette.png              # the world palette's swatch sheet
npm run pixellab -- art sizes <scene>                     # bytes per object and color, against HEAD
npm run pixellab -- object new <name> [--kind sprite|block] [--width W --height H] [--extends character]
npm run pixellab -- scene new <name>                      # a valid, canonical starter source
npm run pixellab -- scene ambient <scene> <item> --duration <ms> --keys '<json>'   # a loop that plays by itself
npm run pixellab -- object action <object> <layer> <name> --duration <ms> --keys '<json>'   # a one-shot the page plays
npm run pixellab -- object state run <object> <state>     # what a state plays, and where it settles
npm run pixellab -- help                                  # every command: scene place, object paint, …
```

**Pixel Lab**, the Mac app, opens the document and draws it with the same engine: it places objects, paints them, plays a scene's motion, and **Publish** (⌘B) is `npm run art`. It must be v0.8.0 or later to open the document, which has states. Its Library sorts the objects into categories, shown as tabs (Terrain, Nature, Buildings, Transport, Industry, Roles, Achievements and Thumbnails), and every object has one. Agents work through its MCP server (`mcp__pixellab__*`), whose edits apply to the document as they're made, or through the CLI above. The loop is edit → `npm run art` → commit the sources (the outputs are git-ignored).

**Pixel Lab for Mac**, the owner's native editor (kept in a separate repository), edits the same sources with the program it bundles, and saves straight to them. Agents reach it through its `pixellab` CLI and MCP server: they look at renders, arrange scenes and paint objects with the same commands, and their MCP edits land in the document as they make them, each a version the owner can review and take back in the app's Versions panel. The `pixel-art` skill (`.claude/skills/pixel-art/SKILL.md`) says when to use which.

Sources are kept in one canonical JSON form, and `npm run pixellab -- check` warns about any source that isn't in it.

### Explainer library

`art/explainer-library.pixellab/` is a separate document of about 100 isometric objects for videos and infographics: a kitchen (for the peer-review analogy), an office, a server room and cloud pieces, AI pieces (robots, tokens, tools, memory), and arrows, bubbles, signs and markers. `docs/intents/2026-10-explainer-library/spec.md` lists every asset and its loop. It uses the site's palette and look, publishes no SVGs, and is never read by the site.

```sh
npm run pixellab -- check --document art/explainer-library.pixellab     # validate it
npm run pixellab -- art preview scenes/sheet-office --scale 3 --out sheet.png --document art/explainer-library.pixellab
npm run explainer-export                                           # every object (one PNG per loop frame) and sheet, 8×
npm run explainer-export -- --scale 4 --out ~/Desktop/explainer    # another scale or folder
```

Open it in Pixel Lab with File › Open Document…. Its five contact sheets (`sheet-kitchen`, `sheet-office`, `sheet-cloud`, `sheet-ai`, `sheet-glue`) show every asset in place. Its Library sorts the objects into seven categories (Kitchen, Office, Cloud, AI, Glue, People and Animals).

`npm run explainer-export` also writes `.explainer-export/explainer.pixellib`, the whole library as a Pixel Lab object library with every category, which another document can import (File › Import Library…, or `pixellab library import`). It's made on demand and never committed. Libraries and palette files are described in the lab's [`docs/libraries.md`](https://github.com/jlawcordova/jlawcordova-lab/blob/v0.8.0/docs/libraries.md).

## Deploy

Pushing to `main` runs `.github/workflows/deploy.yml`, which downloads and checks the pinned Pixel Lab program and builds the art, runs `npm test`, fetches the accomplishments, builds the site, and deploys it to GitHub Pages. Pull requests are tested and built but not deployed. The workflow also deploys `main` when the accomplishments MCP server sends a `repository_dispatch` of type `atproto-updated` (after an add or delete), and daily at 03:17 UTC to catch a missed dispatch. The repository's Pages source must be set to **GitHub Actions** (Settings → Pages → Build and deployment → Source).
